## Як працювати

Код використовує стандартні ES-модулі з явними `import` / `export`. Єдина точка входу — `js/main.js`. Збирач і встановлення npm-пакетів для запуску не потрібні.

На телефоні редагуй потрібний файл у GitHub або github.dev. Після коміту в `main` GitHub Pages публікує оновлення.

Локальний запуск із кореня репозиторію:

```sh
python3 -m http.server 8000
```

Відкрий `http://localhost:8000`. ES-модулі потрібно запускати через HTTP, а не подвійним натисканням на HTML-файл.

Перевірка (Node.js 20 або новіший, без `npm install`):

```sh
npm run check
```

Вона перевіряє завантаження модулів, старі й поточні збереження, незавершені знахідки, переповнений рюкзак та шлях «копання → відкриття → рюкзак → повторний запуск». Це перевірка логіки й даних, а не заміна візуального тесту на телефоні.

## Важливі домовленості

- Збереження залишаються в `localStorage` під ключем `last-signal-v1`, у форматі `{ version: 1, state: ... }`.
- ID предмета — його позиція в масиві `types`. Не сортуй і не видаляй наявні позиції: це зламає старі рюкзаки й колекції. Нові предмети додавай зі збереженням попередніх ID.
- `loadGame()` викликається з `main.js` після завантаження всіх модулів. Не запускай відновлення стану або `render()` під час імпорту інших файлів.
- Функції можуть посилатися одна на одну через імпорти; зв'язки між пошуком, станом і відображенням циклічні. Відкладений запуск у `main.js` робить їх безпечними. Не додавай виклики, що читають ще не ініціалізований стан, на верхньому рівні модулів.
- Стилі підключаються в порядку `base.css` → `search.css` → `excavation.css`. При зміні спільного правила перевіряй усі вкладки.
- Старе посилання `ostannii-syhnal(12).html` переадресовує на поточну гру. Попередні повні версії залишаються в історії Git.
