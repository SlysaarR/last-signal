# Останній сигнал

Мобільна гра про металопошук. Версія 0.34.0 — «Вчися читати сигнал».

[Відкрити гру](https://slysaarr.github.io/last-signal/)

## Вчися читати сигнал — 0.34.0

- Сила й характер відгуку залежать від металу, розміру, глибини та положення котушки. Звуки різних діапазонів, приблизний індекс і стабільність; фольга та прикраси можуть давати схожий відгук.
- 10 відчутних ступенів кожного виду спорядження. Детектор покращує пошук, лопата зменшує витрати, рюкзак додає 3–4 місця за покупку. Вартість копання видно від початку.
- Старі рівні переносяться зі збереженням характеристик і оціненої вкладеної вартості; залишок стає знижкою. Уже зароблений максимум енергії залишається. Купони, предмети й поточна ділянка зберігаються.
- Загальна вартість повної прокачки та ймовірності знахідок не змінені. Перевірено 100 варіантів старих рівнів, 27 покупок, 24 000 модельних ділянок і мобільні сценарії у браузері.

Подробиці, результати й межі перевірки: [quality-034.md](docs/quality-034.md).

## Порядок у деталях — 0.33.0

- Зігнута шайба тепер пласка, з тонким ребром і вигином. Окремі форми отримали болт із різьбою та шестигранною головкою, гострий цвях, язичок банки, пробка, зім’ята фольга й жерсть. Обручки, сережки, браслети та перстені відрізняються конструкцією. Залізо має сталевий відтінок та іржаві плями; золото прикрас більше не зеленіє як латунь монет.
- У рюкзаку, сховищі й колекції немонетні предмети показані мініатюрами тих самих моделей замість непов’язаних emoji. Мініатюри малюються при наближенні до видимої області й мають обмежений кеш.
- Готові, але ще не забрані нагороди — першими в щоденнику. Далі йдуть найближчі до виконання цілі. Уже отримані нагороди згорнуті окремо. Поле не дозволяє забирати нагороди, повторне отримання заблоковане як раніше.
- Прибрано великі постійні кнопки скидання ракурсу: компактна кнопка з’являється на зображенні тільки після повороту. Скидання зразка стану потрібне лише після зміни повзунка. Закриття огляду доступне зверху картки.
- У сміття й уже заповнених позицій альбому немає бездіяльної кнопки додавання. Порожні запаси їжі не створюють рядів вимкнених дій. Після очищення не дублюється пропуск цього ж очищення.
- З вкладки табору в полі можна безпосередньо підтвердити повернення. Переходи між екранами починаються з їхнього верху.

Контент, ID, ціни, нагороди та формат збережень збережено. Перевірки: `docs/quality-033.md`.

## Стан і обертання — 0.32.0

- Знахідки обертаються перетягуванням пальцем чи мишею. Стрілки обертають модель, Home або кнопка повертають початковий ракурс.
- Монети мають дві текстуровані сторони та об’ємний гурт. Прикраси, реліквії й металеве сміття теж мають геометрію для огляду.
- Кожен відсоток стану впливає на колір металу, блиск, рельєф, подряпини й корозію. Малюнок зносу прив’язаний до виду предмета, а не до відсотка: погіршення стану послідовно посилює ті самі дефекти. Однаковий вид і стан відображаються однаково після перезапуску.
- Повзунок у колекції порівнює всі значення 0–100% без зміни знайденого предмета, його ціни чи прогресу.
- У вікні знахідки виправлено пропорції полотна та перекриття підпису кнопкою. Компонування перевірено від 320 px і в альбомній орієнтації.
- Рендер використовує один спільний WebGL-контекст і Canvas-резерв без зовнішніх залежностей. Кадри малюються лише під час взаємодії.

Перевірки й обмеження: `docs/quality-032.md`. Формат збережень, каталожні ID, баланс та кількість контенту збережено.

## Увага до деталей — 0.31.0

Оновлення якості наявного контенту; каталог предметів, 8 місцевостей, 4 напрямки та 12 цілей збережено.

- Рух котушки оновлює лише детектор і поле, не запускає рендер інших екранів; події руху об’єднуються в один кадр.
- Підказка піку та підсвічування котушки відповідають фактичній точності копання навіть на високих рівнях детектора.
- Частково й повністю очищена знахідка відновлюється після перезапуску. Необов’язкове поле `pending.cleanedCells` переноситься також у JSON-копіях; енергія повторно не списується.
- Збереження виконується при згортанні вкладки. Пошкоджені або невідомі збереження не перезаписуються початковою грою: користувач бачить повідомлення й може імпортувати справну копію.
- Великі старі запаси їжі переносяться додому за одну операцію на тип їжі. Тимчасова помилка запису більше не залишає попередження назавжди після відновлення запису.
- В альбомі можна оглядати наявні прикраси, реліквії та архівні предмети. Три ракурси українських монет доступні кнопкою, дотиком і клавішами Enter / Space.
- Другий палець не перехоплює котушку чи очищення; втрата захоплення завершує жест. Модальні вікна огляду та відновлення блокують польові дії.
- Звіт відрізняє кількість оглянутих знахідок від усього принесеного рюкзака. Вартість речей, узятих із дому, більше не позначена як нова здобич.

`npm run check` включає регресії цих сценаріїв. `npm run balance` відтворює модель виїздів для всіх напрямків на трьох рівнях спорядження; припущення і результати — у `docs/quality-031.md`.

## Як працювати

Код використовує стандартні ES-модулі з явними `import` / `export`. Єдина точка входу — `js/main.js`. Збирач і встановлення npm-пакетів для запуску не потрібні.

На телефоні редагуй потрібний файл у GitHub або github.dev. Після коміту в `main` GitHub Pages публікує оновлення.

Локальний запуск із кореня репозиторію:

```sh
python3 -m http.server 8000
```

Відкрий `http://localhost:8000`. ES-модулі потрібно запускати через HTTP, а не подвійним натисканням на HTML-файл.

Перевірка (Node.js 20 або новіший, без `npm install`):

```sh
npm run check
```

Вона перевіряє завантаження модулів, старі й поточні збереження, незавершені знахідки, переповнений рюкзак та шлях «копання → відкриття → рюкзак → повторний запуск». Це перевірка логіки й даних, а не заміна візуального тесту на телефоні.

## Важливі домовленості

- Збереження залишаються в `localStorage` під ключем `last-signal-v1`, у форматі `{ version: 1, state: ... }`.
- ID предмета — його позиція в масиві `types`. Не сортуй і не видаляй наявні позиції: це зламає старі рюкзаки й колекції. Нові предмети додавай зі збереженням попередніх ID.
- `loadGame()` викликається з `main.js` після завантаження всіх модулів. Не запускай відновлення стану або `render()` під час імпорту інших файлів.
- Функції можуть посилатися одна на одну через імпорти; зв'язки між пошуком, станом і відображенням циклічні. Відкладений запуск у `main.js` робить їх безпечними. Не додавай виклики, що читають ще не ініціалізований стан, на верхньому рівні модулів.
- Стилі підключаються в порядку `base.css` → `search.css` → `excavation.css`. При зміні спільного правила перевіряй усі вкладки.
- Старе посилання `ostannii-syhnal(12).html` переадресовує на поточну гру. Попередні повні версії залишаються в історії Git.

## Резервні копії (0.20.0)

У таборі відкрий «Збереження та резервні копії». Експорт створює JSON-файл з поточним станом, включно з виїздом і незавершеною знахідкою. Зберігай файл окремо від даних браузера.

Імпорт приймає лише формат `last-signal-backup`, backupVersion 1, saveVersion 1, максимум 4 МБ. `js/backup-format.js` перевіряє предмети, рівні, числа, колекцію, координати, стан розкопки та місткість. Усі дані попереднього перегляду виводяться через textContent. Старі сирі localStorage-файли не є підтримуваним форматом імпорту.

`js/backup.js` показує попередній перегляд і запитує підтвердження заміни. `installBackupState` спочатку записує попередній стан у `last-signal-before-restore-v1`, потім основний стан і змінює поточний об’єкт перед перезавантаженням, щоб pagehide не перезаписав імпорт старими даними. Якщо запис не вдався, відновлення не виконується.

Кнопка «Копія перед останнім відновленням» відкриває попередній стан для перегляду й підтвердження. Ця копія зберігається лише в тому самому браузері та замінюється наступним успішним записом копії перед відновленням. Вона не захищає від очищення всіх даних браузера — для цього потрібен завантажений файл. Хмарної синхронізації немає.
