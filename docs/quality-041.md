# 0.41 — Польові замовлення

## Поведінка

У щоденнику є три пропозиції: монети певних номіналів, набір типів предметів, вимога до стану. Кожна група має три варіанти — всього дев’ять. Активним може бути одне замовлення. Воно не має терміну виконання, зберігається між виїздами й перезавантаженнями. У таборі є короткий підсумок, у полі — поточні лічильники. Журнал знахідки повідомляє про зарахування й завершення.

Зарахування відбувається тільки при успішному рішенні забрати нову знахідку: у вільне місце, замість предмета чи порції їжі. Залишена знахідка, невдала спроба при повному рюкзаку, старі речі зі сховища, продаж та альбом прогресу не додають. Один предмет збільшує щонайбільше один лічильник; завершений лічильник не переповнюється. Прогрес і розв’язання очікуваної знахідки записуються однією операцією збереження.

Виплата доступна лише в таборі без незавершеної знахідки. Стан замовлення закривається в тій самій операції, що й нарахування купонів: повторне натискання не платить знову. Речі не вилучаються, попередній продаж чи додавання до альбому прогрес не скидають. Після виплати змінюється трійка пропозицій. Скасування потребує внутрішнього підтвердження, скидає тільки поточний прогрес і залишає ту саму трійку. Застаріле підтвердження після заміни замовлення чи відновлення копії нічого не змінює.

## Нагороди й сумісність

Нагороди становлять 24–42 купони за 4–6 відповідних знахідок. Верхня межа — 8 додаткових купонів за кожну зараховану знахідку; частина знайдених речей умовам не відповідатиме. Додаткових купонів за сам виїзд, перевідкриття щоденника чи скасування немає. Це додатковий дохід; фактичну зміну тривалості проходження на гравцях не виміряно. Ціна всіх 27 покращень залишається 206430 купонів. Генерація, шанси, оцінки продажу й енергія не змінені.

Пропозиції обираються за числом виконаних замовлень і не використовують генератор випадковості. Незавершене замовлення тримає стабільний ID та до трьох обмежених лічильників. Нагорода береться з каталогу правил, а не з імпортованого поля. Нове поле `orders` необов’язкове й з’являється лише після прийняття замовлення. Залишаються чинними ключ `last-signal-v1`, оболонка saveVersion 1, backupVersion 1 та всі ID предметів.

Імпорт перевіряє ID пропозиції поточного раунду, безпечне ціле число виконаних замовлень, число лічильників та їхні межі. Пошкоджений локальний файл зберігається для відновлення й не перезаписується тимчасовою новою грою.

## Оптимізація

- Повне оновлення UI викликає побудову інвентарю, майстерні, альбому чи щоденника тільки на відкритому екрані. При наступному відкритті враховуються всі зміни стану. Польовий лічильник рюкзака оновлюється незалежно від майстерні.
- Табірний підсумок зберігає один найкращий стан на тип предмета. Він не створює презентаційні записи й не обчислює ціни для всього сховища. Час обходу лишається лінійним; додаткова пам’ять обмежена кількістю типів каталогу.
- Короткий табірний щоденник і повний журнал мають окремі ключі оновлення. Метрики колекції обчислюються один раз на побудову, а не для кожної цілі окремо.
- Незмінені фотографії монет і стилі зберегли URL кешу попередньої версії. Нових зображень, таймерів чи постійного циклу відмальовування для замовлень немає.

Відкритий інвентар, як і раніше, будує всі картки поточного фільтра. Це оновлення прибирає його роботу в тлі, а не вводить віртуалізацію великого відкритого списку.

## Перевірки

`npm run check`: усі 13 наборів пройдено. Нові набори:

- `orders-check.cjs`: усі дев’ять замовлень, досяжність за чинним каталогом, пороги стану, відсутність витрати RNG при перегляді/прийнятті, повний рюкзак, заміна, залишення, одноразова виплата, незмінність речей та альбому, підтвердження скасування, застарілі дії, частковий прогрес після перезапуску, резервні копії та захист пошкодженого збереження.
- `render-budget-check.cjs`: підсумок 50000 предметів збігається з повним планувальником; 20 повних оновлень пошуку не читають сховище й не змінюють списки карток прихованих екранів; баланс і рюкзак лишаються актуальними; відкриття кожної вкладки підтягує зміни.

Попередні набори перевіряють збереження, розкопку, сигнал, 27 покращень, альбом, захист найкращих копій, групові операції й керування оглядом. Додатково перевірені структура HTML, унікальність ID та локальні URL ресурсів.

Браузерна верстка та фізичний телефон у цьому сеансі не перевірялися. Перевірка кількості операцій не є вимірюванням FPS чи часу завантаження на телефоні.
