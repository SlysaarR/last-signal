# Перевірка 0.52.0 — Зручний щоденник

2026-10-15, Europe/Kiev. Завдання: адаптувати інтерфейс до телефона й ПК, збільшення тексту та клавіатури. Попередня опублікована версія — `dec0161e4b3391468443d7f9fbe774524759ad20` (0.51).

## Реалізація

- Оболонка до 68rem замість фіксованого максимуму 480 px. Пошук обмежений 44rem; довгі одиночні розділи — 56rem. Табір має дві колонки від 48em, колекція — фільтри й результати від 60em. У вузькому режимі порядок у DOM відповідає послідовності на екрані; CSS `order` не використовується.
- Підготовка, карта, напрямок, умови й виїзд зібрані разом. Знахідки для розбору залишаються зверху. Прогрес монет за номіналами можна розгорнути окремо. Колекція й списки використовують адаптивні grid-колонки з обмеженням мінімальної ширини розміром контейнера.
- Всі розміри шрифтів у CSS переведені з px у rem. Раніші підписи 8–11 px мають мінімум .75rem; при стандартному корені це 12 px. Налаштування «Вигляд і зручність» задає 100%, 115% або 130% кореневого шрифту. Масштаб браузера не заборонений; viewport не має `maximum-scale` чи `user-scalable=no`.
- Розмір тексту зберігається окремим ключем `last-signal-text-size`. Він належить пристрою, не входить у сейв гри та експорт/імпорт. При забороні запису зміна діє в поточному сеансі, повідомлення пояснює обмеження. Невідоме значення повертається до стандартного.
- Прибрано конфлікт шапки: старий екран пошуку задавав 40 px висоти, хоча кнопки довідки й звуку займали по 44 px у колонці. Тепер висота автоматична, заголовок і кнопки можуть переноситися.
- Фіксована нижня навігація вимірюється `ResizeObserver`; її реальна висота, включно з переносами й safe-area, використовується у відступі сторінки та прокручуванні. На широкому або низькому екрані навігація перебуває у звичайному потоці. Однаковий розмір не спричиняє повторного запису CSS.
- Переходи переводять фокус на назву розділу, а пошук — на поле для стрілок/пробілу. Початковий запуск не перехоплює фокус; відкритий модальний діалог захищений від переведення фокуса назовні. Навігація має `aria-current`, розділи — підписи, перше посилання дозволяє пропустити шапку. Для карти й щоденника табір позначено як батьківський розділ.

## Перевірено

`npm run check` — **27 наборів успішні**. Додано `interface-check.cjs`: локальне налаштування, повторний запуск, недопустимі значення, блокування сховища, незмінний ігровий сейв, всі переходи фокуса, активна навігація, перенаправлення пошуку в табір, захист модального фокуса, skip-link, реакція на змінену висоту навігації без повторних записів і відновлення незавершеної розкопки.

Існуючі набори перевіряють старі сейви, усі 222 позиції, 27 покупок, економіку, навчання, кар’єру, карту, погоду, розкопку, жести огляду, обмеження малювання мініатюр, кеші й програмний 3D-рендер. Жоден новий цикл `requestAnimationFrame`, таймер чи перерахунок колекції під час руху котушки не доданий. Схема сейву, RNG, ціни й нагороди не змінені.

Окремо перевірено збалансованість HTML, унікальність ID, цілі label/ARIA-посилань, збереження старих ID, сім основних розділів як безпосередніх дітей `main`, єдину версію URL імпортів. `git diff --check` чистий.

Офлайн: **131 ресурс, 3,39 МіБ**, hash `b57128d95e2707bd`. У пакет додані лише CSS та невеликий модуль інтерфейсу; нових зображень і залежностей у runtime немає. Усі 42 попередні фото мають той самий незавершений статус прав; цей випуск не вирішує його.

## Межі доказів

Браузерне керування у середовищі недоступне; візуальні знімки, фізичний Android, реальні клавіатурні/сенсорні дії й screen reader **не перевірені**. VM-об’єкти підтверджують виклики й стан, але не обчислюють CSS-компонування, нативне переміщення фокуса чи висоту реальної навігації. Отже, це реалізація адаптації з функціональними регресіями, не сертифікація доступності або закриття пристроєвої матриці 1.0.

Для живої перевірки: 320×568, 360×800, 800×360, 1280×720 і 1920×1080; усі три розміри тексту, окремо масштаб браузера 200%. Пройти табір → карта → пошук → розкопка → огляд → рюкзак → колекція; перевірити довгі назви, нижні кнопки, відкриті details, офлайн-панель і діалоги. На клавіатурі — Tab/Shift+Tab, Enter, Escape та повернення до поля; на телефоні — повороти екрана й системні відступи.

Наступний етап — аудит завершеного проходження кар’єри: темп доходу/витрат, прогрес цілей і можливі тупики без скорочення довгої прокачки. Автоматична симуляція допомагає знайти проблеми, але людський плейтест лишається окремою умовою релізу.
