# Перевірка 0.51.0 — Швидший огляд

2026-10-15, Europe/Kiev. Завдання: прибрати великі затримки програмного 3D-огляду, зберегти форму й деталі предметів. Це оптимізація fallback без WebGL, а не заява про перевірений FPS телефона.

## Що змінилося

За доступного WebGL гра використовує попередній GPU-рендер. Якщо він недоступний або контекст втрачено, новий `inspection-software.js` малює ті самі трикутники в один буфер кольору та глибини. Один `putImageData` замінив сотні операцій clip/transform/drawImage. Збережено повну геометрію: кількість трикутників і вихідні текстури не зменшувалися.

Глибина визначається для кожного пікселя; порядок трикутників не підмінює перекриття поверхонь. UV обчислюються з перспективою, текстура фільтрується білінійно з обмеженням координат краєм, як у чинному GPU-рендері. Сканування обмежене фактичним перерізом трикутника в рядку, тому вузькі трикутники монет не обробляють великі порожні прямокутники.

Для фото монет використано попередню функцію мікрорельєфу й освітлення. Вона обчислюється тільки для видимого боку. Збільшення й зсув використовують вже освітлену поверхню; новий ракурс або лампа замінюють її кеш. Колір попередньо освітленої фотографії не затінюється вдруге.

Геометрія, вихідні фото, зношення, гурт, отвори й внутрішні поверхні збережені. Переглянуто обидва боки, ребро та стан 12% усіх 14 нових знахідок; окремо обидві металеві групи монет, ракурси та збільшення. Новий облік глибини також прибирає частину похибок старого сортування трикутників за їхнім центром. Це не піксельно ідентичний алгоритм: освітлення металу відповідає чинній формулі GPU, фільтрація й краї стали іншими.

Якщо браузер не дозволяє читати пікселі, лишається попередній Canvas-рендер. У такому режимі прискорення не гарантується. Керування, масштаб 1–2,5, стан предмета, ціни й збереження не змінені; нових таймерів або циклів анімації немає.

## Межі пам’яті

- Один спільний кадр, максимум **300 000 пікселів**. Невеликі зображення мають до двох внутрішніх пікселів на один вихідний у кожній осі; великі обмежуються бюджетом.
- RGBA й Float32-глибина разом займають до 2,4 МБ; окремо є Canvas-поверхня до приблизно 1,2 МБ. Це не оцінка загальної пам’яті браузера.
- Пікселі незмінних текстур читаються один раз і кешуються через WeakMap. Кеш не тримає закриту модель живою. Зберігається лише останній набір освітлених боків кожної живої моделі, а не історія ракурсів.
- Обертання звичайних предметів не створює нових Canvas. Фото монет потребує нової поверхні освітлення при зміні ракурсу, як і раніше; зсув/масштаб її повторно не створюють.

## Контрольні заміри

Node 24.19.0, native `@napi-rs/canvas`, той самий контейнер. Кожна сцена запускається в окремому процесі, вивід 300×250, стан 85%, перший кадр, вісім повторних ракурсів і збільшення 2,5×. Час включає readback готового зображення. Baseline — опублікована 0.50, commit `cd5fdeb2808a23b9b936e10b14cb0f58f218a287`. Повні результати: [inspection-benchmark-051.json](inspection-benchmark-051.json).

| Предмет | Медіана повторного кадру 0.50 | Медіана 0.51 | Прискорення | Перший кадр 0.50 → 0.51 |
|---|---:|---:|---:|---:|
| Бубонець, 2032 трикутники | 93,5 мс | 17,3 мс | 5,4× | 345,6 → 42,7 мс |
| Наперсток, 1152 трикутники | 51,9 мс | 5,2 мс | 10,0× | 228,4 → 59,3 мс |
| Прямокутна пряжка, 288 трикутників | 19,7 мс | 5,9 мс | 3,3× | 62,9 → 24,6 мс |
| 25 копійок, 1024 трикутники | 78,5 мс | 15,3 мс | 5,1× | 183,1 → 59,7 мс |

Найдовші повторні кадри 0.51 у цьому прогоні: 46,9 / 20,5 / 13,2 / 31,9 мс відповідно. Це коротка вибірка з прогріванням JIT та паузами середовища, не стабільні 60 FPS. Створення моделі/текстур виміряне окремо й не включене в кадр: 14,5 / 18,0 / 6,9 / 60,0 мс у 0.51; цей початковий етап ще коштує часу.

Раніші заміри близько 300–360 мс для бубонця робилися на нових Canvas, тому їх не слід напряму ділити на медіану прогрітих кадрів. У таблиці наведені однакові методики. Початковий багатопредметний прогін старого renderer завершився сигналом 137 після двох моделей; причин цього окремого завершення не встановлено, у порівняльні цифри його не включено.

Відтворення: `CANVAS_MODULE=/path/to/@napi-rs/canvas npm run benchmark:inspection`. Для старої версії вказати `INSPECTION_ROOT` на її окремий checkout/archive. Нативна залежність використовується тільки для локального QA, у гру та офлайн-пакет не входить.

## Перевірки

`npm run check`: **усі 26 наборів успішні**. Новий `software-render-check.cjs` перевіряє перекриття в обох порядках малювання, прозорість, відсікання зворотних граней, очищення старого кадру, масштаб/зсув, бюджет роздільності, незалежний перетин променя з похилою площиною для UV, суцільний діагональний шов, отвори реальних моделей, ліниве читання видимого боку та збереження попередньо освітленого кольору.

Попередні набори підтверджують жести, клавіатуру, об’єднання подій в один кадр, скасування кадру при закритті, всі 222 предмети, 27 покупок спорядження, прогрес, підказки, сейви та офлайн. `finds-art-check.cjs` відмалював 56 ракурсів/станів, сторінки переглянуто. `inspection-art-check.cjs` пройшов для фото, рельєфу, зношення та лампи; порівняльні зображення до/після переглянуто. Нативний benchmark перевіряє одноразове читання вихідних текстур, повторне використання поверхні та кешу освітлення.

Офлайн: **129 ресурсів, 3,37 МіБ**, hash `94669a2b99a5525d`. Схема сейву, каталог, імовірності, джерела фото та права на матеріали не змінені.

Браузерний QA у поточному середовищі недоступний. Реальний телефон, фактичні жести/звучання, GPU-контекст, тривалий сеанс і пам’ять пристрою ще потребують перевірки. Це не закриває всю матрицю 1.0. Наступний етап — компонування інтерфейсу на телефоні та ПК, фокус і збільшений текст.
